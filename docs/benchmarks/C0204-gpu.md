# C0204 FastDVDnet CPU/GPU diagnosis

The saved GUI session selected FastDVDnet at strength 2 for C0204: 1920×1080,
100 fps, 27.84 s, 2,784 frames. The installed `.venv-models` runtime was CPU-only
(`AzureExecutionProvider`, `CPUExecutionProvider`). The RTX 3060 Ti and driver
580.178.04 were verified working on the host; the missing GPU runtime, not the
hardware, prevented GPU neural inference.

FastDVDnet runs before the parallel color queue. Its original 128-pixel CPU
tiles produce 240 network calls per HD frame; color workers wait for the temporal
denoiser. The old source-fps progress throttle then withheld frame updates until
25 more frames on 100 fps footage. The result queue also unnecessarily held
ready color output while collecting more expensive denoised frames.

## Changes

- A separate `.venv-gpu` runtime, leaving the active CPU process/environment alone.
- CUDA/cuDNN preloading and actual session-provider reporting.
- Backend/frame/tile progress before inference and during tile processing.
- Encoded-frame updates based on wall-clock time instead of source frame cadence.
- Immediate release of ready color results, while retaining ordered bounded queues.
- Validated GPU-only dynamic-shape FastDVDnet variants: whole-frame inference up
  to HD, larger halo tiles above HD, and a 4 GiB CUDA arena limit.
- FP16 internal GPU arithmetic with float32 I/O; optional float32 GPU selection.
  The validator measured maximum error 0.00292 and mean below 0.00025 against
  GPU float32 on random, dark, and bright inputs. A variant is not registered
  until GPU validation succeeds. GPU inference failures explicitly return to
  the original bounded CPU tile path.

## GPU checks

An ORT profile recorded 141 CUDA kernel events for the original network. The
app then selected the GPU-only full-frame model and produced valid HD output.
A six-frame end-to-end GPU render retained all six frames, dimensions and
cadence, emitted CUDA progress messages, and did not fall back to CPU.

| App denoise path | Warm HD prediction time |
| --- | ---: |
| Original 240-tile CUDA path | about 1.03 s/frame |
| Full-frame CUDA FP16 path | about 0.377 s/frame |

The latter predicts roughly 17.5 minutes of denoising for 2,784 frames.
This is an inference-stage estimate from a few frames, not a completed full-clip
export measurement. Transfer conversion, decoding, color and encoding add work.
Neural denoise is still substantially more expensive than conventional denoise.

91 CPU-environment tests passed; 13 neural/parallel tests also passed with the
real GPU runtime. Ruff and the wheel build passed. The running GUI export was
not canceled, restarted or reconfigured.

## Use

Cancel the CPU export, save the project, close that app instance, and relaunch
from the checkout:

```bash
UWCC_INFERENCE_DEVICE=auto .venv-gpu/bin/python -m uwcc
```

See [GPU setup and model details](../ai-workflow.md#gpu-environment-on-this-machine).
Turning off the FastDVDnet checkbox retains conventional denoise at the chosen
strength. The earlier `local-ai-stabilized-full.mp4` review used conventional
denoise, not FastDVDnet.
